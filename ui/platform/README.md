# PilotDeck 独立管理平台

本目录提供账户、管理后台、模型代理和钱包服务。客户电脑继续运行本地 PilotDeck；平台服务器不执行客户的终端或电脑操作。

当前为可本地验收的开发版本，不是已经部署到公网的商业发行版。完整边界见 [实施状态](../../docs/superpowers/plans/2026-10-29-client-admin-status.md)。

## 本机启动与登录

在仓库根目录运行以下 PowerShell 命令：

```powershell
$env:PATH = "$PWD\.cache\runtime\node-v22.23.1-win-x64;$env:PATH"
node ui/platform/setup.mjs --local
node ui/node_modules/vite/bin/vite.js build --config ui/platform/admin/vite.config.js
powershell -ExecutionPolicy Bypass -File ui/platform/start-local.ps1
```

启动脚本优先使用 `http://127.0.0.1:3100`，占用时选择其他空闲端口，实际地址记录在 `.pilotdeck/platform/service.json`。这个地址同时提供后台页面和接口，不需要额外启动后台前端开发服务器。

初始管理员邮箱和随机密码位于 `.pilotdeck/platform/administrator.txt`。此文件、`platform.env` 和数据库都必须保密，不能提交或打包进客户端。初始化脚本不覆盖已有配置，也不重置已有管理员密码。

本机开发管理员邮箱不接收邮件。生产初始化必须通过 `--email` 指定自己的管理员邮箱。邮件服务未配置时，自助注册与邮件找回密码返回不可用，后台仍可创建客户账号。

管理员账号同时只保留一个有效登录会话。密码验证成功的新登录会在同一事务内替换全部旧会话，不受普通客户设备名额限制；错误密码不会影响当前登录。升级启动时保留管理员最近一次未过期登录，清理其它管理员会话，普通客户的设备限制和会话不变。

后台页面每 15 秒检查会话，重新聚焦或切回页面时也会检查；旧凭证在服务端立即失效。休眠、离线或浏览器节流可能延迟页面跳转，恢复连接后再次检查。升级前已经打开的页面需刷新一次才能加载自动检查功能。

## 配置模型与客户

1. 在“模型与价格 → 模型渠道”添加渠道，填写自定义名称、服务地址、协议和 API Key。一个渠道可以关联多个模型，连接信息只维护一次。
2. 点击渠道的“获取模型”，搜索、勾选模型，设置输入和输出售价后导入。也可在“模型管理”点击“添加模型”，选择渠道后手动填写模型名称。已有模型标为“已导入”，重复导入不会覆盖原售价。
3. 在模型表单或导入窗口选择应用范围，并启用渠道及模型。新模型默认停用，未分配应用会提示客户端不可见。默认模型仍在“应用管理”设置。
4. 在用户管理中创建普通客户，或配置邮件后允许客户注册。后台管理账号不能作为客户账号启动托管客户端。
5. 配置注册赠送，或者生成兑换码交付客户。示例金额不会被自动当作正式售价或赠送参数。

渠道的“测试连接”只读取模型列表，不发送生成请求；列表接口不支持不代表模型无法调用，可改为手动添加。模型的“测试连接”会发送短生成请求，服务商费用由运营者承担，不记入客户账单；完整模型能力仍需实际验证。模型名称是上游调用标识，显示名称供客户选择。内部标识自动生成，同一个上游模型可在不同渠道分别配置。

协议选项区分 OpenAI 官方、OpenAI 兼容接口和 Ollama；官方选项保留其输出参数适配，Ollama 可不填密钥。其它协议沿用 Responses、Anthropic、Google。已有渠道保留原服务商适配。Google 模型名称带不带 `models/` 前缀视为同一模型，不会重复导入或覆盖原价格。

批量导入的每个模型可单独配置名称、能力、输入/输出售价和启停状态；也可给已选模型批量填价。应用范围应用于本次选中模型。导入在一个事务内完成，任何校验失败均不写入，失败重试保留标识。没有勾选的模型不会创建，已有模型不会被批量覆盖。

每批最多导入 100 个模型，每个应用最多分配 5000 个模型；导入、单模型分配和应用设置采用相同的应用限制。

输入、输出售价保留为必填项。Token 上限和模型能力放在默认收起的“高级设置”中，新建模型默认输入上限 65536、输出上限 1024、仅文本能力；这些是平台初始限制，不代表服务商的实际能力，应按供应商支持范围调整。输入上限包含系统提示、历史和工具定义，过小会在请求发出前触发上下文超限。客户端将输入与输出上限合计为总上下文，再为输出保留预算，不重复扣减输入额度。编辑已有模型保留其原有限额和能力。获取列表不会创建或启用模型，也不扣客户余额。列表中的模型不一定支持所选调用协议，保存后仍应测试连接，再启用并分配给应用。

编辑渠道时可留空 Key 使用已保存密钥；修改基础地址或协议后，必须重新填写 Key 才能保存。请求只由管理员通过后台发送，服务商的原始响应与密钥不会直接传回浏览器。OpenAI 兼容、Responses、Anthropic 和 Google 列表接口均已接入；不提供列表接口的服务商会提示手动填写。分页最多读取 5 页、总响应不超过 2 MiB，结果不完整时会明确标记。

启动时会事务迁移旧模型的连接信息，保留模型标识、价格、限额和应用分配；旧记录各自生成独立渠道，避免误合并不同密钥。渠道停用后，关联模型从客户目录隐藏，代理也拒绝新调用。有关联模型的渠道不可删除，需先把模型移到其他渠道。升级前请按下面的备份步骤保存数据库；回退旧版需恢复对应旧版数据库备份。

后台售价采用“元/百万 Token”。API 的 `inputPriceMicros`、`outputPriceMicros` 是每百万 Token 的人民币微元价格，1 元等于 1,000,000 微元。底层资金用整数的万亿分之一元存储，账单的 `amountUnits` 保留微额消费，不能用浮点余额覆盖数据库。

每次调用按配置的输入和输出上限预留余额，再按服务商返回的实际用量结算。因此余额必须满足预留要求；上限应结合真实模型设置。用量缺失、流中断或超出预留范围会进入待核查，保留预留资金、释放请求并发名额。管理员核实后选择结算或释放，必须填写原因和证据；不能拿估算 Token 充当实际用量。

## 邮箱验证码

管理后台的“邮件设置”（`/#mail`）支持 QQ 邮箱和 Foxmail 邮箱的 SMTP 授权码：

1. 填写发件邮箱、发件人名称和 16 位邮箱授权码。
2. 勾选“启用验证码邮件”并保存。也可先保持停用，保存后测试邮件，再启用。
3. 填写测试收件邮箱，点击“发送测试邮件”，到收件箱或垃圾邮件文件夹确认收信。
4. 在“注册与默认值”中保持注册开关开启，客户即可申请注册验证码；找回密码使用同一发件配置。

服务地址固定为 `smtp.qq.com:465`，启用 TLS 及证书验证，无需填写域名、端口或协议。授权码使用平台已有加密密钥加密存入数据库，不返回浏览器，也不会写入审计日志。保存后留空表示保留原授权码；更换发件邮箱时必须重新填写对应授权码。修改即时生效，无需重启后端或重新打包客户端。

测试邮件只允许管理员主动触发，每分钟最多 3 次、每小时最多 20 次。测试成功表示 SMTP 服务器已接收邮件，不代表收件箱一定可见。验证码仍为 6 位、10 分钟有效，发送失败会使该次验证码失效；原有发送频率限制继续有效。

旧的 HTTPS 邮件接口环境变量仍兼容；只有从未保存 SMTP 配置时才使用这些变量。显式停用 SMTP 后不会自动改用旧接口：

```dotenv
PLATFORM_MAIL_URL=https://your-mail-adapter.example/send
PLATFORM_MAIL_TOKEN=your-private-service-token
PLATFORM_MAIL_FROM=your-verified-sender@example.com
```

旧接口发送 HTTPS POST，使用 `Authorization: Bearer <token>`，JSON 为 `{from,to:[email],subject,text}`。适配服务应在成功接受邮件时返回 2xx。这些环境变量不是 SMTP 配置，也不是对任意邮件厂商 API 的通用兼容声明。邮件凭据只放服务器；验证码不返回客户端或打印到日志。

## 托管客户端

本机已构建的源码环境可双击仓库根目录 `Start-Client.cmd`，或者从根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File apps/desktop/scripts/start-managed.ps1
```

此入口默认连接 `http://127.0.0.1:3100`，先检查账号平台可用，再编译桌面代码并打开客户登录窗口。需要已有根项目和主 UI 构建、已安装的 Electron 运行文件；它是源码开发入口，不是面向客户分发的安装包。后台登录页面仍在 3100，原本地 Web 页面仍在 3001。

在线登录后先进入“我的账户”，可查看余额、兑换、账单、设备和模型价格，进入对话或学习；手动刷新同步后台模型授权。后台可先创建普通用户来体验，管理员账号不能用于客户登录。自助注册和找回密码需要上一节的邮件服务；没有模型时显示未开放状态，不会使用开发者已有密钥。

开发入口的账号数据与日志在 `.pilotdeck/client`。每个账号的学习端口会保存在自己的目录内，避免与原 3001 本地版争用；已保存端口被其它进程占用时会报错，不能靠静默换端口导致历史存储丢失。换平台地址时先退出当前客户版，再使用 `-ServiceUrl https://your-platform.example` 参数。

开发运行时设置 `PILOTDECK_MANAGED_URL=http://127.0.0.1:3100`。托管启动先显示客户注册/登录窗口，通过身份校验后才启动本地运行时。账号数据与浏览器存储分区按服务地址和用户编号隔离；退出先结束旧账号进程树。

正式打包沿用项目现有 Windows 打包流程，并在其环境中设置：

```powershell
$env:PILOTDECK_DISTRIBUTION = 'managed'
$env:PILOTDECK_MANAGED_URL = 'https://your-platform.example'
```

打包脚本只把公共 HTTPS 服务源写入 `managed-service.json`。不要向构建环境提供服务器的模型密钥、管理员密码或数据库加密密钥。开发态允许回环 HTTP，正式包要求 HTTPS。没有这些环境变量时保留原有本地运行模式，现有 `localhost:3001` 浏览器部署不会自动成为托管客户。

客户端新版本由后台发布 Windows x64 版本号、说明、HTTPS 安装包地址、字节大小和 SHA-256。下载不携带账户 Token，检查大小和摘要后仍需用户确认安装。开发运行不安装更新。安装包生成、签名和实际安装尚未完成验收。

真实桌面验收（先构建主 UI 并编译桌面端）：

```powershell
$env:CUSTOMER_DESKTOP_TEST = '1'
node --test ui/platform/customer-desktop.test.js
```

此测试启动临时平台及真实 Electron 窗口，使用隔离邮件接收器与模拟模型，验证注册、兑换、聊天账单、学习 iframe 和账号切换；结束后关闭测试实例并清理临时账户，不修改正在使用的后台数据。

## 服务器部署

`package.json` 和 `package-lock.json` 可独立安装服务及后台依赖。Docker 构建上下文是本目录：

```sh
cd ui/platform
cp .env.example .env
# 编辑 .env：替换全部模板密钥，设置真实管理员及邮件服务
docker compose config --quiet
docker compose up -d --build
```

`PLATFORM_ENCRYPTION_KEY` 至少 32 字符，应使用随机生成值并独立备份。更换此值不会自动轮换现有加密数据；错误密钥会使服务拒绝打开数据库。初始管理员密码至少 12 字符，启动后修改环境变量不会重置已有账号。

Compose 只将接口映射到宿主机 `127.0.0.1:3100`。公网入口需要另行配置可信 HTTPS 反向代理、域名或相应证书。代理应支持长连接和流式响应，关闭响应缓冲。不要直接将客户电脑上的 PilotDeck 本地服务暴露为多用户平台。

当前部署文件按单实例 SQLite 设计，不可让多个容器共享同一数据库文件并行处理请求。运行目录为 `/data`，Compose 使用持久卷。容器运行用户为 `node`，若改成宿主机绑定目录须配置写入权限。

后台前端已在仓库外单独安装依赖并构建，验证了依赖和字体路径的独立性。开发机全新安装的原生 SQLite 依赖遇到下载中断，回退编译又缺少 C++ toolset；这不影响已运行的本机依赖，但完整镜像安装仍须在目标环境验证。

`PLATFORM_TRUST_PROXY` 默认不信任转发来源。启用 `loopback` 仅适用于代理连接实际来自回环地址的部署；Docker 网络里的代理来源不一定是回环地址，不能为了读取客户 IP 而随意信任任意转发头。

已检查 Compose 配置；当前开发电脑 Docker 引擎未运行，镜像构建及服务器容器运行尚未验证。

## 备份与恢复

运行中的 SQLite 使用专用备份脚本，不能只复制主文件而遗漏 WAL：

```powershell
node ui/platform/backup.mjs .pilotdeck/platform/platform.sqlite D:/private-backups/platform-2026-10-29.sqlite
```

容器示例：

```sh
docker compose exec platform node backup.mjs /data/platform.sqlite /data/backup-2026-10-29.sqlite
docker compose cp platform:/data/backup-2026-10-29.sqlite /your-private-backup-directory/
```

脚本创建一致快照，并验证完整性与外键；目标已存在则失败，防止覆盖。应把备份传到独立受控存储，并单独保存加密密钥。建议每天备份，保留 7 日、4 周版本；这里没有自动部署备份定时任务。

恢复时先停止平台，归档当前数据库及其 `-wal`、`-shm` 文件，在空的目标数据位置放入备份，恢复对应的加密密钥和文件权限，再启动。不要把备份主文件与旧 WAL 混用。恢复后核对账户、余额、流水和待核查请求，并在真实运营前进行隔离环境恢复演练。测试已覆盖含 WAL 和超大精确金额的备份恢复。
